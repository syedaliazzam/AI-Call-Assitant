# ADR-0039: v1.0.3 overlay fixes, the answer line, and on-screen visual checks before release

- **Status:** Accepted (developer, 4 Nov 2026)
- **Date:** 2026-11-04
- **Architecture reference:** `docs/architecture/kite-architecture-v3.1.md` §5 (compact view, live session), §6 (answer rules); version 3.14.0
- **Supersedes / superseded by:** adjusts ADR-0033 (panel opacity: storage key, fade), ADR-0035 (no acrylic on Windows; default size; expanded mode), ADR-0037 (answer line), ADR-0038 (in-call microphone states)

## Context

The developer's real test of v1.0.2 found the overlay solid, the opacity slider without effect, ⛶ not opening, the microphone not working, and answers that did not open with one short line to say. v1.0.2 had been checked by unit tests only. The developer asked that every visual item be verified on the real screen before release.

## Causes found

1. **Solid panel / slider without effect.** "Fade when the pointer is elsewhere" was on by default and painted the panel at 100% under the pointer, and the overlay started as "hovered", so the panel stayed solid until the pointer had entered and left it. Moving the slider means the pointer is on the overlay, so the slider never showed. An old stored opacity (the window-opacity key, default 1) could also pin it. On top of that, Windows' acrylic, measured on the real screen, blurs what is behind into unreadable colour.
2. **⛶ "doesn't open".** It only hid the live-words row; the window did not change, so it looked like nothing happened.
3. **Microphone "doesn't work".** Both voice paths worked on the real microphone in the real shell (below). The overlay's top-left microphone, where the reference has its microphone button, was only a status icon, so pressing it did nothing; the dictation button was hidden in the Chat box. A dictation that heard nothing stopped silently after 15 s, and the main window's listening state was barely visible.
4. **Answers.** The rules allowed a 15-word headline that often carried the details, and did not forbid "Here are…" or "based on my CV".

## Decision

1. **Opacity (ADR-0033 adjusted):** a new key `kite.overlayPanelAlpha`, migrated once from the old key (1 or anything ≥ 0.95 becomes 70%; a lower choice is kept, clamped to 40–100%). "More see-through when the pointer is elsewhere" replaces fade, is off by default, and never paints the panel more solid than chosen (`paintedOpacity()`). The overlay starts un-hovered.
2. **Windows: no acrylic** (ADR-0035 adjusted). The window stays transparent; the 70% tint and the text shadow keep the text readable. macOS keeps vibrancy.
3. **⛶ expands the window:** a new shell mode `expanded` (as tall as the work area, up to 960 wide, centred); "Back to compact" and Esc return to the full overlay's place.
4. **Overlay layout:** default 640×480 (minimum 560 wide); tighter rows; one Clear and one ⛶ on the answer row; the live-words row shows only the level bars and the chips (clicking them opens the transcript); key hints on Answer (Ctrl↵), Screenshot (Ctrl⇧↵) and Chat (Ctrl⇧⌫) down to the minimum width; the call timer; "Question:" in the normal text colour; "Um" and "Uh" left out of the chips.
5. **Microphone:** the overlay's top-left microphone is the dictation button (red and pulsing while listening, with a status line); "Didn't catch a question…" after 15 s of silence, in the overlay and the message box; the message box's microphone is solid red while listening; a microphone blocked by Windows or held by another app says so.
6. **Answer line (current rules; v-previous unchanged):** one short sentence, at most 12 words, said at once; never "Here are", "Here is", "So", "Well", "Sure", "Based on", "According to", "As per", nor a label; no mention of the CV, resume, documents or notes in any line; a list question names the items in the answer line, then one bullet per item. The card shows a bold "Answer:" before it (a label the model writes is dropped).
7. **Visual checks before release:** a rig (`apps/web/tests/visual/`) serves the overlay with realistic state, the Ask Kite voice path (`/mic`) and the real live page (`/call`); drivers in `apps/desktop/tests/visual/` run the real desktop shell against it, put a real browser window (a pinned shell window on a Wikipedia page) behind the overlay, and capture the real screen.

## Measured (4 Nov 2026, this laptop, Windows 11, dev desktop shell)

- Overlay over Wikipedia at 70%, 40% and 100%; expanded (960×672) and back (640×480) with the button and with Esc; the script bar; 560 px wide with every key hint and End; the microphone listening. Captures: `docs/testing/v1.0.3-screenshots/`.
- Real microphone, Windows speech through the speakers: the Ask Kite path heard and sent "WHAT PRODUCTION GRADE APPLICATIONS HAVE YOU BUILT"; in a real call, the message box's microphone sent "What production grade applications have you built" (another run: "And what production great…") as the question, kept out of the transcript; no page errors.
- 3 real answers (Haiku, $0.0010): one answer line each (13, 12 and 12–14 words by a plain word count, "900 ms" counting as two), 3–4 bullets, an optional Tip, no meta opener and no CV mention.

## Consequences

- Without acrylic there is no blur on Windows: the meeting shows through the 70% tint, readable but busy behind long text. The slider and the tint are the controls.
- The rules change is checked on 3 answers only (no paid evaluation, as asked).
- The production install could not be driven (it needs a signed-in account); the checks ran the same code in the dev shell against a local rig.

## Alternatives considered

- Keep acrylic as a bonus: rejected on the real screen (content behind unreadable).
- A second, separate microphone button in the overlay: the top-left one, where people press, is the button.
